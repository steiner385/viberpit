# ViberPit backlog priority assessment — 2026-09-12

Reviewed 68 initially open, unclassified records (67 issues and one design PR). Applied scores to 61: 23 are now classified, 37 now need human review, and one in-progress item received scores only. Seven capability-link reports are verified resolved and await closure through this PR. This assesses the remaining unscored backlog; it does not claim these engineering issues are implemented. Source evidence is each linked issue body and existing capability assignment. Log observations are historical and their root causes remain hypotheses until reproduced. Account identifiers, host addresses, session IDs, and raw logs are omitted.

The existing [RICE implementation](../../server/pm/score.py) computes reach × impact × confidence / effort. Inputs follow the existing [classifier convention](../../server/pm/classification.py): integers 1–5. For this assessment, reach estimates affected workflows/users, impact estimates disruption, effort estimates relative implementation scope, and confidence estimates evidence strength. Higher effort lowers priority. These are ordinal planning estimates, not measured population or time units. Existing non-null inputs are preserved. No new scoring implementation or priority-label scale is introduced.

Rows marked `classified` are assessed sufficiently for normal queue consideration, subject to current board state, dependencies, claims, policy, and live verification. Rows marked `needs_human` receive an explicit decision or evidence hold; their input state was unclassified. Neither a score nor this document authorizes dispatch, changes an existing parked state, clears dependencies, approves a design gate, or waives a maintenance window. Parent epics and PRs are coordination/review records, not runnable leaf issues. The rebrand work keeps its initiative and moves to operator experience as part of the separate capability retirement.
