# Native replacement and pending root proof

A native handle replacement inside one application driver lifetime can erase the predecessor from later shutdown observations. Before discarding a handle, either verify its complete managed work tree stopped or retain durable/sticky uncertainty. A clean replacement does not retroactively prove a failed predecessor close.

Sibling sweep: Codex clear and permission-profile replacement now share the managed-tree guard, preserving goal/policy checks. Claude clear now retains uncertain SDK teardown across later closes. Existing separate-driver lifetimes remain represented independently by the operation execution store.

A second asymmetric-state failure registered not-entered child work but left root reservations without a generation. Real queue cancellation and launch-hold denial then had no safe proof path. Root and child now share the same pending generation representation. Only terminal durable cancellation can attest it; native entry is serialized with ownership release and rejects stale operations before effects.

Validation: protocol-backed native replacement tests plus real queue/hold lifecycle and delayed drain/stale approval races on SQLite and disposable Postgres. No proof is inferred solely from an absent driver or a UI terminal label.
