4 · Where a prompt goes §4 architecture, one round trip

Browser · AssistantSheet

Second socket channel getSocket('assistant'); sends prompt + context; renders with the existing transcript, composer and cards.

→

Edge · FastAPI

POST /api/assistant/session (one per identity) mints the ccas1: token; the session WebSocket streams events; identity from the tailnet as today.

→

Daemon · SessionDriver (kind = assistant)

Real claude process, built-ins disabled, mcp_servers={"ccswitch": in-process}, custom system prompt, max_turns, effort=low.

↺

Tools → loopback API

Each tool = one endpoint call with Authorization: Bearer ccas1:…, X-CCSwitch-Via: assistant; loopback-only, route-allowlisted, audited with via.

Structural defences that do not rely on the model behaving: no shell/file/web tools · only the ccswitch MCP server · route allowlist on the token · cards for every mutation · destructive never auto-allowed · tool and prompt rate limits · idle reap · kill switch CCSWITCH_ASSISTANT_ENABLED (§8).
